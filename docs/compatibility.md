# Codex compatibility

The implementation was checked against the installed Codex CLI `0.171.0`, its `codex resume --help`, and the observable layout under `~/.codex`. The current installation contains `session_index.jsonl` entries with `id`, `thread_name`, and `updated_at`, and rollout files under `sessions/YYYY/MM/DD/*.jsonl` whose initial metadata contains `id`, `cwd`, and `timestamp`. On the inspected installation, subsequent `event_msg` records include `task_started`, `task_complete`, `turn_aborted`, and `item_completed` with top-level timestamps. Metadata timestamp is treated as the session's initial time, not as proof of its most recent activity. These observations do not establish a stable format for other Codex versions.

User tasks are read only from `response_item` records whose payload is a `message` with `role: "user"` and `content` items of type `input_text`. Developer messages, tool records, metadata, and other response items are excluded. Codex may prepend an environment-only `input_text` block or append that block to a real user message; CZI removes it only when the structured block contains the expected cwd, shell, and current date fields.

CZI keeps the native `thread_name` and the first real user task as separate fields. The former is used for the Session column; the latter is only a bounded Preview and never changes the full Session ID or recovery command.

Names and activity are aggregated separately per full session ID. Empty names never replace a valid one; valid timestamped names outrank names with invalid or absent timestamps, and ties use the last record in the index. The latest valid index activity timestamp, metadata `updated_at`, or timestamp of a recognized session activity event determines the displayed and sorted activity time. If none exists, the initial metadata timestamp is used, followed by file modification time as a last resort. CZI streams the entire session file to find activity events, while extracting the preview only from the first 64 records; large histories therefore take longer to scan.

Session IDs are accepted only from `session_meta.payload.id` (with the legacy `session_id` field as a fallback on that same record). Message IDs such as `msg_...` and tool call IDs are never used as session IDs. The standalone binary uses an inline Ratatui viewport on `/dev/tty` with a continuous selected index and scroll offset; PageUp/PageDown move by the visible window rather than changing discrete pages. Crossterm 0.28 writes its inline cursor query to stdout; CZI temporarily redirects stdout to the tty for this synchronous query and restores it before writing any result. During the picker, stdin also points to the controlling terminal so Crossterm cannot read a different terminal; it is restored before launching Codex. These process-wide operations rely on the picker remaining single-threaded. CZI starts normal event handling only after initialization. The internal selector emits a NUL-delimited cwd and Session ID on stdout (exit 0); cancellation emits nothing (exit 2), and errors exit 1. Optional Bash/Fish integration continues to use a private `mktemp -d` directory with a mode-0600 result file. This preserves paths containing whitespace or newlines without shell evaluation. The Shell removes the result file and directory before changing cwd and invoking the Rust resume path. A controlling terminal is required to show the selector.

These files are not a stable public API. CZI treats the index as optional, skips malformed lines, and requires both a real session ID and recorded cwd before marking a record resumable. The exact Codex build used at runtime is still responsible for accepting the session ID.

The repository contains only synthetic test data; no real Codex session is copied into it.
